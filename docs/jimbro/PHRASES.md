# Jim’s local phrase catalog

`lib/jimbro/phrases.ts` contains the 100 supplied content seeds verbatim, with stable `seed-001`–`seed-100` identifiers, plus original supplemental lines. Every runtime record has an event, exact tone, separate flirtation flag and an explicit requirements array. Supplemental content has stable contextual IDs; editing copy must retain its ID unless it is a different remark.

The frequent start, set and rest categories have at least five non-flirtatious alternatives in each exact tone after their ordinary event conditions are satisfied. Less frequent deadline and completion categories are also expanded across all four tones. Quiet copy stays brief, encouraging copy supports flexible plans, playful copy adds light jokes, and unhinged copy uses absurd cucumber bureaucracy rather than unsafe intensity. Error copy never says that a write succeeded.

## Truth gates

- Set and completion events require confirmed persistence (`saved`).
- Progress copy requires a saved, verified comparable personal best (`saved`, `personalBest`); this conservative rule prevents generic improvement claims from being triggered by an arbitrary set.
- Warning, preparation and departure events require an actual deadline. The controller must still choose the correct phase; eligibility is not itself proof that cutoff has occurred.
- Welcome-back language requires existing history. References to a previous session require an available previous session; a claim that it left notes requires a previous record with notes, not an arbitrary historical record.
- The professor line requires a real class commitment. The controller should set `class` from an explicit commitment type, never infer class solely from an arbitrary title substring.
- Remarks about a changed plan or shortened session belong only in the short/recovery event, after the controller has established that context.
- Appearance-directed compliments and more personal charm/blushing jokes are separately flirtation-gated. Flirtation is off by default.

This is a finite authored bank, not infinite novelty. The selection engine must keep bounded persistent history, event receipts, recent exclusion, cooldowns and shuffle bags; exhausted eligible pools need a least-recently-used fallback. A one-line pool may eventually repeat. An empty pool should produce silence, with essential scheduling/error information still displayed independently of Jim.

The catalog is product copy derived from Harvey’s supplied brief and new original supplemental copy. It is not evidence of interviews, usability findings or training advice. No runtime AI service is needed.
